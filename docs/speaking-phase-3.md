# SpeakCheck Phase 3

## Operating the pilots

| Capability | Switch | Scope |
| --- | --- | --- |
| Adaptive conversation | `SPEAKING_STRUCTURED_ENABLED=true` and `SPEAKING_ADAPTIVE_ENABLED=true` | Exposes the guided editor and simulation on the teacher’s activity launch page. Version 1 plans remain readable and runnable through the structured flag. Clearing the adaptive flag stops version 2 authoring. It leaves previously launched version 2 sessions usable while structured mode stays on. |
| Read Aloud | `SPEAKING_READ_ALOUD_ENABLED=true` | Exposes original practice at `/speak/read-aloud` and teacher-owned passage import, assignment, transcript submission and moderation. Independent of the two older pilot switches. |
| Diagnostics | `VITE_SPEAKING_LOCAL_DIAGNOSTICS=true` | Includes the standalone `/speak/prepare` route in the web build, including long-reading measurement. |
| Provider-independent operation | `SPEAKING_PROVIDER_INDEPENDENT_ONLY=true` | Restricts the process to configured local-only pathways and preserves queued legacy jobs. Use for dedicated school staging. |
| Local development | `SPEAKING_MOCK_MODE=true` | Provides the legacy mock adapters used when the independent-only restriction is off. |

The Phase 3 flags default to false. Use a disposable API and database. Apply `npm run prisma:deploy` against a loopback test database, then start `npm run dev`. A teacher can open any suitable existing SpeakCheck activity, or create one with the existing editor. At launch, select **Structured conversation** and load a template or author questions and objectives. Open **Simulate conversation** and enter examples for ordinary, alternate, negative and unclear responses. The existing activity supplies title, scenario, mode, rubric and allowed Help. The two provided templates suit selected School English past-event and preference tasks. They leave the original library activities intact. The launch saves the exact plan with the session. The guided editor currently configures a single launch, and the existing result visibility applies.

For reading, select **Read Aloud**, import and preview eligible passages, then choose Grade → Textbook → Unit → Part. Confirm the reference and optionally set four weights adding to 100. A zero weight disables that criterion. Launch the session and use its QR code or six-character code. The student sees the assigned reference and can choose and preview a recording before transcribing it. The original-practice route has the same linked selectors and processes practice locally without a teacher account. A classroom session accepts one submitted recording per participant. The teacher can create another session for a new formal attempt.

The student can transcribe before the session starts and submit when it opens. A retry reuses the same transcript and submission identifier in the open tab. If a refresh follows a saved submission, opening the session recovers the saved turn and can restart finishing. If the page is left before anything is saved, select the local file again. Read Aloud accepts browser-decodable files within 90 seconds and 20 MiB. WAV is the baseline for the local smoke and long-recording measurement. Containers and codecs such as MP3, M4A, MP4, WebM and Ogg depend on browser decoding. Validate the actual files created by each school’s devices. The student is told in Japanese or English when decoding fails. Device-generated playback for the passage, individual sentences and flagged words uses an installed local English voice if available.

Use **Class results** to see joined, submitted, processing, review and confirmation counts. Open the first unreviewed reading or select a participant. Review the original reference, device transcript, marked discrepancies and provisional criterion scores. Enter the scores supported by direct observation and leave the others N/A. Confirm or confirm and open the next unreviewed student. Reopening appends a revision. The student can refresh to read the latest confirmed scores and comment.

## Passage import

The existing School English textbook crosswalk provides source references and vocabulary. It contains no verified full passages. The reading catalog is teacher-owned and stores immutable passage versions separately from those references. Imports match normalized grade, textbook, publisher, edition, unit and part. An identical import keeps its existing version. A correction to the title or text creates a new version under the same key, and a differently identified edition has its own catalog entry. Existing sessions keep the exact assigned reference and rubric. The launch selector shows the latest version of each catalog entry.

The [original sample catalog](examples/speakcheck-read-aloud.original.json) is a complete format example. The import envelope has `formatVersion: 1` and an array of up to 30 passages. Each passage has `grade` (integer 1–12), `textbook`, `edition`, `unit`, `part`, and `text`. `publisher` and `title` are optional. The verified reading text may contain line breaks and is bounded to 3,000 characters and 350 normalized words. Use the text the student should actually speak. For dialogue, remove speaker labels and stage directions in the draft if students should omit them. Keep pagination and commentary outside the text.

The local converter understands explicit grade, Unit and Part or Read and Think headings in the two supplied plain-text layouts. Run the command with the correct edition determined from the source material. Omit `--output` for an aggregate-only inspection. Add `--output` with a new, private directory outside the repository to write reviewable JSON batches and source line locators.

```powershell
node scripts/speakcheck-textbook-import.mjs --source '<private text file>' --format here-we-go --edition '<verified edition>'
node scripts/speakcheck-textbook-import.mjs --source '<private text file>' --format new-horizon --edition '<verified edition>' --output '<private directory outside the checkout>'
```

The dry run found 64 candidates and 13 flagged sections in Here We Go, and 66 candidates and four flagged sections in New Horizon. It wrote no passage files. The converter flags duplicate locators, missing context, and several unsupported formats. It skips content outside recognized headings, including some special sections. Review every candidate against the original edition and resolve anomalies before using the upload preview. Textbook text belongs in a teacher’s authorized private catalog. The committed fixture and browser tests use original material.

## Architecture and fair grading

| Boundary | Phase 3 implementation |
| --- | --- |
| Browser recognition | Reuses the pinned q8 Moonshine worker, WebAssembly runtime, Cache Storage and retry behavior. Long reading splits decoded audio into approximately 15-second non-overlapping chunks, preferentially at low-energy frames. The worker receives waveform data without the expected reference. Chunks run sequentially and a missed voiced segment makes the aggregate transcript uncertain. Splitting can still affect words around a boundary. |
| Conversation | Replays persisted turns from an immutable plan. Version 2 adds phrase alternatives, authored alternate and negative follow-ups, question and repetition handling, a single clarification per prompt, explicit completion limits and self-correction within an answer or its immediate follow-up. Contractions and a small synonym map help cue matching. Author cues for short meaningful fragments and valid alternatives. Open-ended semantic understanding and general grammar scoring require separate validation. |
| Submission | Existing teacher and participant authorization, session/revision handling, join codes, rate limits, idempotent turn IDs and durable evaluation jobs. Read Aloud accepts validated transcripts and advisory duration through the dedicated transcript content type. A teacher-owned assignment snapshot selects the reading evaluator. Audio bodies and Help requests are rejected on the reading path. |
| Provisional evidence | Evaluation metadata records version, algorithm, configured recognizer revision, criterion rules, cited turn IDs and uncertainty. Reading also records reference version, alignment and reported duration. Teacher views link adaptive objectives to actual saved excerpts. The server validates data shape and session association. A device-generated transcript remains an unverified claim about the audio. |
| Moderation | Read Aloud uses the existing session results and individual record pages. PostgreSQL stores teacher decisions as append-only revisions. A version check rejects an edit when another reviewer has already changed the record. Only an authenticated owning teacher can read the audit history and write a revision. The participant token can read its own current result. |
| Historical data | One additive migration adds private catalog and review tables and a nullable session snapshot column. It leaves existing application tables and queued evaluation jobs intact. Both new tables enable RLS without public policies. The application API enforces teacher and participant access. |

The [structured engine](../apps/server/src/speakingStructured.ts) and [reading evaluator](../apps/server/src/speakingReading.ts) run inside the [existing API route and evaluation lifecycle](../apps/server/src/routes/speakingRoutes.ts). [Shared reading contracts](../packages/shared/src/speakingReading.ts) define imports, review input and alignment. The [repository](../apps/server/src/speakingRepository.ts) and [additive migration](../prisma/migrations/20261127000000_speaking_read_aloud/migration.sql) persist the evidence. The browser uses the [existing worker](../apps/web/src/features/speaking/localSpeech/speech.worker.ts) through the [shared recognizer](../apps/web/src/features/speaking/localSpeech/browserSpeech.ts). The teacher workspace hosts [launch setup](../apps/web/src/features/speaking/teacher/SpeakingReadingSetup.tsx) and [moderation](../apps/web/src/features/speaking/SpeakingReadingResults.tsx). The [student upload and practice flow](../apps/web/src/features/speaking/SpeakingReadAloud.tsx) uses the same result contracts.

**Reading metrics.** Alignment reuses deterministic word-level Levenshtein reconstruction. Normalization folds case, punctuation, common contractions, hyphen separators and English number equivalents from 0 through 99. WER is (substitutions + omissions + insertions) divided by reference token count. Coverage is (matches + substitutions) divided by reference token count. WER can exceed 100%. A final omission flags a potentially incomplete reading. An adjacent repeated insertion can be flagged as possible repetition. These are discrepancies relative to the device transcript. Display them as possible differences until the teacher verifies the reading.

**Reading rubric.** The default weights are 35% accuracy, 25% pronunciation, 25% fluency and 15% expression. The only automatic level is accuracy when the transcript has adequate structural evidence. Its experimental bands are 4 at 95%, 3 at 80%, 2 at 65%, 1 at 40%, and 0 below 40%, where accuracy is one minus WER clamped at zero. The bands are engineering defaults awaiting teacher calibration. N/A stays separate from zero. Acoustic criteria remain N/A until observed by a teacher. No combined grade is shown. Approximate matched words per minute may appear for a sufficiently long, non-uncertain recording. It reflects normalized matches per recording minute, including pauses. Duration, signal energy, silence, and clipping cannot establish pronunciation or fluency. The current voice gate helps identify very quiet or nearly constant recordings. It cannot reliably identify speakers or classroom noise.

## Semantic benchmark

MiniLM q8 is a viable Transformers.js/ONNX candidate at about 23 MB for quantized weights and runs on CPU. The published checkpoint is Apache-2.0. Transformers.js supports browser ONNX WebAssembly and experimental WebGPU, which still needs device qualification. The pilot remains deterministic because a sentence similarity score alone confuses contradictions and near matches with changed facts. On synthetic developer-machine text, cosine ranked changed weekday (0.953) and quantity (0.912) above an equivalent soccer preference (0.741). Negated soccer scored 0.791. The deterministic engine requires authored evidence and can hold unclear answers for review. It can also miss a valid paraphrase if the teacher did not provide a suitable cue. [Model checkpoint](https://huggingface.co/Xenova/all-MiniLM-L6-v2/tree/751bff37182d3f1213fa05d7196b954e230abad9) · [ONNX Runtime Web support](https://onnxruntime.ai/docs/get-started/with-javascript/web.html)

`node --import tsx scripts/speakcheck-semantic-benchmark.mjs` uses synthetic pairs only. The initial Node CPU run fetched 23,685,047 bytes and initialized in 16.29 s. Single embedding latency was 4.38 ms median and 6.54 ms p95 (20 samples). Process RSS grew from 112 MB before initialization to 193 MB at initialization, with 187 MB after inference. A second run initialized in 779 ms with 0.71 MB observed fetch. Deterministic decision times were about 0.007–0.008 ms median for v1 and 0.015 ms for v2 in the same harness. Browser initialization, concurrent Moonshine/embedding memory use and student-response accuracy were outside the Node measurement. Shipping the extra model would add roughly 0.95 GB across 40 cold devices. Phase 3 adds zero semantic model bytes to student devices.

## Privacy and retention

Read Aloud retains the submitted transcript, provisional evidence and teacher moderation on the application server. Raw recording and preview stay in the active page/device, with the preview URL revoked when the file is replaced or the page closes. Neither Phase 3 mode uses an external AI provider and there is no fallback. Browser model downloads use public, revision-pinned assets. Google’s public Gemini Developer API terms restrict services directed at or likely to be accessed by under-18s. Existing provider code remains for separately authorized use, with school qualification based on the independent-only configuration. [Google Gemini API additional terms, age requirements](https://aistudio.google.com/docs/terms#age-requirements)

Optional retention and private playback are deferred. Live Supabase storage usage, exact project allowance, consent and authorized retention periods were unavailable. Use a teacher-observed assessment for acoustic criteria. An authorized pilot would first need a private bucket, separate consent and retention policy, and verified headroom. Use expiring single-object upload grants, opaque keys, ownership checks at initiation/finalization/playback, server-side metadata and content validation, and a duration/byte budget. Keep incomplete uploads separate from accepted evidence. Issue expiring playback URLs on demand, and run explicit expiration/manual deletion and orphan reconciliation with audit records. Decide the cleanup policy and quota behavior on staging before connecting any school data.

At 48 kbit/s, an illustrative mono compressed recording is about 180 KB at 30 seconds, 360 KB at 60 seconds or 540 KB at 90 seconds, before overhead. Quality for teacher assessment still needs a listening validation. At 60 seconds this is 14.4 MB for a class of 40, 43.2 MB for 120 students, and 180 MB for 500 students. Two attempts double those totals. One daily class of 40 over 30 days would store approximately 432 MB, before playback egress, if all files were retained. 60 seconds of mono PCM at 16 kHz takes about 1.92 MB. The current experiment adds zero stored recording bytes. Compare future usage against actual capacity. Supabase lists 1 GB file storage and 5 GB each of uncached and cached egress on Free. Forty cold Moonshine clients can fetch about 1.28 GB of model files plus approximately 0.87 GB of runtime artifacts before compression, caching and reuse. Render cold wakes and GitHub Pages bandwidth also constrain a free pilot. [Supabase pricing](https://supabase.com/pricing) · [Render free limits](https://render.com/docs/free) · [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

Chrome on the Windows development machine (Intel Core i5-7200U, two physical cores) processed repeated original speech with Moonshine q8/WASM. Cold preparation took 30.79 s with 32,079,632 model bytes. Cache-only startup took 5.75 s and downloaded zero model bytes. Each duration had three runs while other local verification was active. With three runs the p95 is the maximum observed. The distribution is too small for device capacity predictions.

The repeated fixture had 0% WER for the Moonshine runs. The silent clip produced no speech, the 91-second clip was rejected, and an invalid WAV returned a decode error. These measurements use a single synthetic voice with repeated sentences. Paused, noisy, quiet and self-correcting learner recordings require authorization and separate measurements. Browser peak memory was outside this run. Reproduce with Vite on loopback, `SPEAKING_E2E_WAV` set to the original English fixture described in `scripts/speakcheck-reading-benchmark.mjs`, and `node scripts/speakcheck-reading-benchmark.mjs`.

Its median/p95 transcription times were 12.37/16.78 s at 15 s, 14.86/15.71 s at 30 s, 22.25/22.88 s at 60 s, and 22.56/47.89 s at 90 s. The smaller Moonshine model remains the only assignment download. The existing diagnostics can compare Whisper Tiny and Base separately.
